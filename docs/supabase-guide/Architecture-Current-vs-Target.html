Current → Target: what actually changes

One config line moves the app from the left column to the middle. The right column is what that line does not do for you.

Area Current state Target state Work required
Mode switch auth-config.js has no authMode, so LOCAL_MODE = true authMode: "supabase" present; both code paths already exist in index.html Edit one file, redeploy. Reversible by deleting the line.
Where passwords live SHA-256 hashes in LOCAL_ACCOUNTS[], shipped inside the page. Old plaintext values remain in git history. Supabase Auth holds them. Nothing password-shaped is delivered to the browser. Create each account in the dashboard with a new password. Never reuse one that was ever in the repo.
Who can sign in Only the two hard-coded accounts. Public sign-up setting is irrelevant because Auth is unused. Only accounts the owner creates — provided public sign-ups are disabled. Authentication → Providers → Email → turn sign-ups OFF. Do this before switching, not after.

Pricing engine Runs entirely in the browser. Invoices and contract rates never reach Supabase — before or after the switch. Nothing. This is the part the switch deliberately does not touch.
Dead config file authconfig.js exists and is loaded by nothing. Editing it has no effect. Gone. GAP 3 — delete it, so there is one config file and one place to look.

Order of operations

  1. Export current settings to a file.
  2. Turn public sign-ups OFF.
  3. Create accounts — tick Auto Confirm User.
  4. Set app_metadata.role for the admin.
  5. Run schema.sql and login_history.sql.
  6. Deploy both Edge Functions; disable enforced JWT on admin-users.
  7. Set Site URL and Redirect URLs.
  8. Switch authMode on a preview URL first.
  9. Sign in, re-import settings, verify the Admin tab.
  10. Promote to production.

How to tell it worked

  • The BUILD timestamp in the header moved forward — otherwise you are looking at a cached page, not a broken switch.
  • Signing in with a deliberately wrong password fails at Supabase, not instantly in the page.
  • The Admin tab appears for the admin account and not for a normal one.
  • The Admin tab lists real accounts — that proves admin-users is reachable.
  • A second sign-in shows up in login_history.

Rollback

Delete the authMode line from auth-config.js and redeploy. The app returns to local-account mode and the old per-machine data — still under its local:: prefix — becomes visible again.

Nothing written to Supabase during the trial is destroyed by rolling back; the two modes read different tables.

The one-way part is the accounts and passwords you created — those stay in Supabase, unused, until you switch again.
