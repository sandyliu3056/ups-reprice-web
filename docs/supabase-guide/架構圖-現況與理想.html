現況 → 理想:到底改了什麼

一行設定就把左欄變成中欄。右欄是那一行不會幫你做的事。

項目 現況 理想 要做的事
模式開關 auth-config.js 裡沒有 authMode,所以 LOCAL_MODE = true 加上 authMode: "supabase";兩條路的程式碼本來就都在 index.html 裡 改一個檔、重新部署。把那一行刪掉就退回來。
密碼存在哪 SHA-256 雜湊寫在 LOCAL_ACCOUNTS[],跟著網頁一起送出。以前的明碼還留在 git 歷史裡。 Supabase Auth 保管。沒有任何密碼形狀的東西送到瀏覽器。 每個帳號都在後台用全新的密碼建立。曾經進過 repo 的密碼一律作廢。
誰進得來 只有寫死的那幾個帳號。公開註冊的設定無所謂,因為 Auth 根本沒在用。 只有你親手建的帳號 —— 前提是公開註冊已經關掉。 Authentication → Providers → Email → 關掉註冊。切換之前做,不是之後。
帳號 ID
(ME.id)		 "local::<帳號>" Supabase 給的那組 UUID 缺口 1 —— 每一把 localStorage key 和 IndexedDB 的名字都掛著它。目前沒有任何搬遷程式。
加人 / 移除人 改 index.html、commit、重新部署。在部署上線之前,那個人還進得來。 後台,或 App 裡的 Admin 分頁。他手上的 token 一過期就進不來。 想在 App 裡管就要部署 admin-users;只用後台的話什麼都不用做。
角色 寫死陣列裡的 role 欄位 —— 任何人打開網頁都看得到 app_metadata.role,寫在 JWT 裡。使用者自己改不動那一欄。 一個管理者跑一次 update auth.users。跑完要登出再登入 —— 角色是跟著 token 走的。
登入狀態 sessionStorage 裡的一段 JSON(勾了「保持登入」就進 localStorage) Supabase 的 session,token 會自動換新 什麼都不用做,用戶端自己處理。
費率設定同步 local_settings,走兩個 SECURITY DEFINER 函式,鑰匙是 sha256("cfg-sync::"+帳號+"::"+密碼) user_settings,一個帳號一列,RLS 依 auth.uid() 跑 supabase/schema.sql。注意:之前存在同步鑰匙底下的設定不會跟過來 —— 切換後再存一次。
帳單歷史同步 local_history 的 RPC —— 有在用,gzip 壓縮,只增或覆蓋 沒有。histPush/histPull 不是 LOCAL_MODE 就直接跳出。 缺口 2 —— 需要一張依 auth.uid() 的表加 RLS,做 local_history 已經在做的事。不補就是功能倒退。
登入紀錄 本機的活動紀錄 —— 只有這一台瀏覽器 login_history,由 record_login() 寫入;身分和時間由伺服器從 JWT 取;只有主帳號讀得到 跑 supabase/login_history.sql。失敗的嘗試和 IP 仍然要看 Supabase 自己的 Auth Logs。
Admin 分頁 只能列出寫死的帳號,不能改 透過 admin-users 完整管理帳號 部署函式,然後把它的「Enforce JWT verification」關掉 —— 函式自己驗來人,比平台那層更嚴。
地址查詢 ups-address Edge Function —— UPS 金鑰存成函式 secret 完全不變 什麼都不用做。
計價引擎 完全在瀏覽器裡跑。帳單和合約費率永遠不會到 Supabase —— 切換前後都一樣。 什麼都不用做。這正是這次切換刻意不去碰的部分。
沒用的設定檔 authconfig.js 存在,但沒有任何地方載入它。改它不會有任何效果。 刪掉。 缺口 3 —— 刪掉它,讓設定只有一個檔、一個地方要看。

動作順序

  1. 把現在的設定匯出成檔案。
  2. 關掉公開註冊。
  3. 建立帳號 —— 記得勾 Auto Confirm User。
  4. 幫主帳號設 app_metadata.role。
  5. 跑 schema.sql 和 login_history.sql。
  6. 部署兩支 Edge Function;把 admin-users 的強制 JWT 驗證關掉。
  7. 設定 Site URL 與 Redirect URLs。
  8. 先在 preview 網址切 authMode。
  9. 登入、把設定匯回來、確認 Admin 分頁在。
  10. 再改正式站。

怎麼知道成功了

  • 標題列的 BUILD 日期往前走了 —— 沒走就是拿到快取的舊頁,不是切換失敗。
  • 故意打錯密碼,失敗是在 Supabase 那邊發生,不是網頁立刻擋下來。
  • 主帳號看得到 Admin 分頁,一般帳號看不到。
  • Admin 分頁列得出真的帳號 —— 這證明 admin-users 通了。
  • 第二次登入會出現在 login_history 裡。

要退回去

把 auth-config.js 裡的 authMode 那一行刪掉,重新部署。網站回到本機帳號模式,原本那些掛在 local:: 前綴底下的本機資料又看得到了。

試用期間寫進 Supabase 的東西不會因為退回去而消失 —— 兩種模式讀的是不同的表。

唯一回不去的是你建的那些帳號和密碼 —— 它們會留在 Supabase 裡閒置,直到你下次再切過去。
