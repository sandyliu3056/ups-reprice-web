UPS 地址驗證 API
設定手冊

住宅／商業判定改用 UPS 地址分類
對象:管理者(部署代理、設定金鑰)與使用者(在網站上填一次網址)
需要:UPS 開發者帳號、Supabase 專案、命令列
預估時間:約 30 分鐘(第一次)
專案 ref:snalvdjsnysutmkqjyaa

§1為什麼需要一個「代理」

瀏覽器不能直接打 UPS:UPS 要 OAuth 金鑰,而且會被 CORS 擋掉。所以中間放一個 Supabase Edge Function,由它拿著金鑰去問 UPS,前端只丟地址、收回結果。

瀏覽器
送出地址
沒有任何金鑰
→
代理(Edge Function)
UPS 金鑰放在這裡
驗證呼叫者身分
→
UPS
地址驗證 + 分類
回 R / C / U

R = 住宅、C = 商業、U = 判不出(判不出就退回系統判定)。

金鑰為什麼不做成網頁上的欄位 網頁上填的東西會存進瀏覽器的 localStorage、同步成雲端那筆設定,而且會跟著匯出的設定檔一起送出去。UPS Secret 放進去,等於這三個地方任何一份到了誰手上,誰就有你的金鑰。金鑰只用命令列設在代理那一端。

§2先在 UPS 申請

到 developer.ups.com 建一個應用程式,務必加上「Address Validation」這個產品,拿到 Client ID 與 Client Secret。

只開 Rating 或 Tracking 是不夠的 代理打的是 POST /api/addressvalidation/v2/3,結尾的 3 是 request option 3 =「地址驗證 + 地址分類」。沒有這個產品,第 6 步會拿到 502 UPS 403。

§3裝 CLI、登入、連結專案

# 登入(會開瀏覽器要你授權)
supabase login

# 在 repo 根目錄執行,會產生 supabase/config.toml
supabase link --project-ref snalvdjsnysutmkqjyaa

目前 repo 裡還沒有 config.toml,所以第一次一定要先 link。

§4設金鑰 —— 先用測試環境

supabase secrets set \
  UPS_CLIENT_ID=你的id \
  UPS_CLIENT_SECRET=你的secret \
  UPS_BASE=https://wwwcie.ups.com

UPS_BASE 指到 UPS 的測試站(CIE),不會燒正式額度。等全部測通再切正式站(§7)。

SUPABASE_URL 與 SUPABASE_ANON_KEY 不用設,平台會自動提供。

§5部署

supabase functions deploy ups-address

§6一層一層測

這個代理最好用的地方是:錯誤碼會直接告訴你卡在哪一層。照順序測,不要跳。

6a — 確認部署成功(不帶任何憑證)

curl -i -X POST \
  "https://snalvdjsnysutmkqjyaa.supabase.co/functions/v1/ups-address" \
  -H "Content-Type: application/json" -d "{}"
回傳意思
401 not signed in部署成功了。它擋你是對的 —— 沒有登入本來就不該讓過
404沒部署成功,回 §5

6b — 拿一個 token

到 Supabase 後台 → Authentication → Users → Add user,建一個測試帳號(email + 密碼,記得勾確認)。然後:

curl -X POST \
  "https://snalvdjsnysutmkqjyaa.supabase.co/auth/v1/token?grant_type=password" \
  -H "apikey: <auth-config.js 裡的 anonKey>" \
  -H "Content-Type: application/json" \
  -d "{\"email\":\"test@example.com\",\"password\":\"你設的密碼\"}"

從回傳裡抓 access_token。

6c — 真的打一次

curl -X POST \
  "https://snalvdjsnysutmkqjyaa.supabase.co/functions/v1/ups-address" \
  -H "Authorization: Bearer <剛剛的 access_token>" \
  -H "Content-Type: application/json" \
  -d "{\"address\":\"1600 Pennsylvania Ave NW\",\"city\":\"Washington\",
       \"state\":\"DC\",\"postal\":\"20500\",\"country\":\"US\"}"
回傳意思 / 怎麼修
{"class":"R"｜"C"｜"U"}全通了。可以進 §7
500 UPS credentials not configured§4 的 secrets 沒設到。重設即可,不用重新部署
502 UPS 401UPS 的 Client ID / Secret 打錯
502 UPS 403UPS app 沒有 Address Validation 產品,回 §2

卡住看 log:

supabase functions logs ups-address

§7測通了才切正式站

supabase secrets set UPS_BASE=https://onlinetools.ups.com

§8在網站上設定

設定分頁 →「住宅／商業判定來源」→ 點設定住/商判定來源。

關閉 = 放棄 面板裡的「關閉」不會保留變更,只有「儲存設定」會寫進去。改到一半反悔,按關閉就好。

§9目前的限制 —— 請先讀完

網站現在跑「本機帳號模式」,填了網址也不會生效 代理會檢查呼叫者是不是真正的 Supabase 使用者。本機帳號模式沒有 Supabase 登入,所以每一個地址都會撞上 401 not signed in,結果一律退回系統判定。

這不影響你先做完 §1–§7。那七步驗證的是「代理 + UPS 金鑰」這一段,和登入模式無關,做完就是永久的資產。等登入模式切到 Supabase、資料搬遷完成之後,§8 填上去就會通。

一個帳號一組 API 的話

如果每個同事要用自己的 UPS 額度,代理要改成「按使用者查金鑰」:一張只有伺服器讀得到的表,存每個人的 Client ID / Secret,代理用呼叫者的身分去撈自己那組。網址仍然大家共用一個。

這件事的前提一樣是先有真正的使用者 —— 本機帳號模式下大家共用一把 anon key,伺服器分不出誰是誰。

§10開啟之前務必先量

API 是最優先的判定來源,不是「補判不出來的那些」 程式裡 API 的答案排在帳單代碼與歷史之前。只要 API 判得出來,就會蓋掉原本的判定 —— 包括帳單上明明寫著住宅代碼的那些。

也就是說,打開它會讓很多貨件的住/商改變,收費跟著改變,不是只影響少數不確定的幾筆。

建議做法:先只在自己的帳號開啟,拿同一期帳單跑兩次(開 / 關),比對總額與住商筆數,確認 UPS 的地址判定和你的帳單代碼有多常不一致。確認過再給同事,否則等於全公司一起換掉計價依據,卻沒有人量過差多少。

§11疑難排解速查

現象原因
畫面顯示「已選連動 API 但沒有填代理端點」網址欄是空的。§8 填上
「API 代理呼叫失敗(HTTP 401)」沒有有效登入 —— 見 §9
「API 代理呼叫失敗(HTTP 404)」網址打錯,或函式沒部署
「API 代理呼叫失敗(HTTP 500)」代理上的 UPS 金鑰沒設。回 §4
「N 個地址呼叫失敗」部分失敗,那幾筆用系統判定,下次重算會自動重試
「API 沒有回傳任何住/商分類」UPS 對這批地址都回 U(判不出)
選了 API,面板卻顯示「系統設定」端點沒填。畫面顯示的是實際生效的來源
