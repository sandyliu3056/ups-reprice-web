本版變更(在 b7daea4 之上):

1. 同期 RTN+ADJ 拆段
   SCC 運費行說明沒有 Undeliverable Return(= 改的是前期原出貨)時,
   退件回程與 ADJ 各自成段、各自判住/商、各自計價,LPS 不再軋成負數。
   SCC 說明帶 Undeliverable Return 的是改回程本身,照舊與 RTN 併段。

2. 退件回程住/商規則變更
   看回程自己:帳單代碼優先,沒有代碼判商業。不再沿用原出貨、不查歷史。
   (舊版原出貨是住宅的退件會跟著判住宅。)

3. 匯入格式驗證
   主帳單與帳單歷史匯入都逐檔驗:要同時有 1Z 開頭 18 碼追蹤號、
   數字開頭帳單號、可辨識的帳單日期。不符的跳錯、不進帳單歷史。

4. Rating Breakdown 改版
   追蹤號深色橫幅、每期金色色條標帳單號;一段一張卡,左 UPS 實收、
   右重新計價,左邊框顏色分住宅(紫紅)/商業(藍);卡頭掛渠道、
   Zone、計費重、日期;最後一條深色合計條。
   查不到費率的金額標紅加虛線底,滑鼠停留顯示原因。

5. Dashboard 改版
   上排三格算式:向客戶收 − UPS − 帳戶層費用,標題列金底分隔。
   費用組成與渠道改甜甜圈,各自帶 Unknown 紅色切片
   (未知 ACC 代碼與 NPF/SCF 進費用組成;服務名認不出的件進渠道)。
   Zone 保留長條。「未判定」卡列出查不到費率筆數、住/商判不出的原因分列、
   NPF/SCF 金額、未知代碼與代碼清單;有東西才顯示,金額未計入重算總額。

【不要上傳網站】(Supabase 用,設定過就不必再跑)
  supabase/schema.sql             -> Supabase 後台 SQL Editor 執行一次
  supabase/login_history.sql      -> 同上
  supabase/functions/admin-users/ -> supabase functions deploy admin-users
  supabase/functions/ups-address/ -> 只有要用「連動 API」才需要:
        supabase functions deploy ups-address
        supabase secrets set UPS_CLIENT_ID=... UPS_CLIENT_SECRET=...
        再把函式網址填進「設定」分頁的 API 端點欄
